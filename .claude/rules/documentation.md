Documentation should be completed at the end of every large task set, meaning if you have been told to complete a certain amount of work then at the end of that implementation you should document the core pieces that you touched and how they work.

Documentation should be kept up to date as the project and tasks progress. Always use high level explanations in documentation. Documentation should live in the /docs directory and be filed under an existing markdown file. 

If the documentation does not seem related to existing markdown files in the docs folder, you can create a new markdown file, but follow the naming conventions of all caps and underscores for multiple words.

Do NOT create unnecessary amounts of documentation when completeing tasks throughout the project.
