# Command Center: 1-Day Build Plan

A minimal personal dashboard with a daily news briefing, today's tasks, notes, goals and powerlifting training. Local LLM calls and one tool-calling agent sit on top of plain CRUD.

> **Status:** the Stack, Architecture, Data model and Model features sections below describe what is built. The phase checklists under Tasks are the original build plan and are not kept as a progress tracker; they still mention plain JS, a single agent input box and other choices that changed. How each part works now is in `architecture/` (`AGENTS.md`, `DATABASE.md`, `FRONTEND.md`, `TRAINING.md`).

## Stack

| Layer | Choice | Notes |
|---|---|---|
| Frontend | Vue 3 + Vite + TypeScript, Vue Router, Vitest | Vite dev server proxies `/api` to FastAPI. Serving `frontend/dist/` from FastAPI is not implemented; the app runs in dev mode |
| API | FastAPI | One app in `api.py` plus routers for agent actions, the study buddy stream and training |
| DB | Postgres 16 (Docker Compose) | SQLAlchemy 2.x + psycopg, schema managed by Alembic migrations (see `architecture/DATABASE.md`) |
| LLM | Ollama, `qwen3.5:2b` | Via `langchain-ollama` `ChatOllama`. Upgrade to a larger Qwen if tool calls are unreliable |
| News | RSS via `feedparser` | Feed list lives in `backend/services/news/feeds.json` |
| Tools | FastMCP server | Task and note tools for agents, streamable HTTP on port 8765 |
| Dev stack | Docker Compose, `make up` | Postgres, Ollama, migrations, API, MCP server and frontend in one command |
| Tracing | LangSmith | Env-var driven, so LangChain calls are traced automatically. `@traceable` covers non-LangChain steps. Can be switched off with one env var |

## Principles

1. **CRUD first, AI second.** Tasks and notes work with no LLM. Agents enhance them.
2. **Small tool surface.** Each agent gets 2-3 narrow tools. No agent can delete anything.
3. **Never block the UI on the LLM.** Briefings are generated by a job and cached in the DB. Agent calls are explicit button presses with loading states.
4. **Cut scope before cutting sleep.** See the cut list at the bottom.
5. **Trace everything agent-related.** Every agent run is visible in LangSmith, so debugging a bad tool call starts from the trace, not from guessing.
6. **Tracing is optional and privacy-aware.** The app must run with tracing off. Traces send prompts and outputs (your tasks and notes) to LangSmith's cloud, so mask or disable it for personal content if that matters to you.

## Architecture

```
frontend/                         Vite + Vue 3 + TypeScript (src/api.ts, pages/, components/, composables/)
        |  fetch /api/*  (Vite proxy strips the prefix)
backend/services/api/             FastAPI app (api.py) and routers: agent_routes, study_buddy_routes, training_routes
backend/services/news/            RSS fetch (news.py), briefing service (briefing.py), feeds.json
backend/services/mcp/server.py    MCP tools over crud/
backend/ai/llm/                   single-shot model calls and prompts
backend/ai/agents/                tool-calling agents (runner.py, study_buddy/)
backend/crud/                     all SQL; crud/schemas/ holds request models
backend/models/                   Pydantic response models
backend/db/                       models.py, session.py
backend/alembic/versions/         migrations 0001 to 0005
docker-compose.yml, backend/Dockerfile, Makefile
```

### Data model
Mirrors the Pydantic models in `backend/models/`. All ids are UUIDs (`gen_random_uuid()`), `date_created` defaults to the current date. ORM in `backend/db/models.py`, migrations in `backend/alembic/versions/` (`0001_initial` to `0005_training`).
- `tasks`: id, title, type (enum `WORK`/`PERSONAL`), requirement, due_date, completed, date_created. Indexed on (due_date, completed)
- `notes`: id, title, content (text, one markdown document), date_created, summary, summary_generated_at, summary_source_hash (latest AI summary, nullable)
- `news`: id, title, summary, quiz_section (jsonb list of `{question, answer}`), sources (text[]), date_created. Indexed on date_created
- `goals`: id, title, details, target_date (optional deadline, used as the meet date), date_created
- `weak_points`: id, note_id (cascades on note delete), topic, resolved, date_created; one row per topic per note, case-insensitive
- Training: `training_maxes`, `programs`, `program_sets`, `workout_sessions`, `lift_sets` (see `architecture/TRAINING.md`)

### Model features

| Feature | Kind | What it does |
|---|---|---|
| News briefing | single call | Summarizes the day's RSS items into a title, summary and quiz; `POST /news/refresh` |
| Plan my day | single call | Orders due tasks with estimates and gives a week status and goal checks; `POST /agents/task/actions/plan_day` |
| Summarize note | single call | Stores a summary apart from the note's content; `POST /agents/notes/actions/summarize_note` |
| Balance my week | single call | Judges tasks against gym days and suggests changes; `POST /agents/training/actions/balance_week` |
| Study buddy | tool-calling agent | Quizzes the user on a note over SSE and records weak points; `POST /agents/notes/study_buddy/stream` (no UI yet) |

Single calls get their data from the route and return structured output the route validates. The MCP server exposes `create_task`, `list_tasks`, `update_task`, `complete_task`, `create_note`, `search_notes` and `append_note_content`, with no delete tools. Details are in `architecture/AGENTS.md`.

## Tasks

### Phase 0: Setup and risk check (~1 hr)
- [ ] Pin deps in `requirements.txt` (fastapi, uvicorn, sqlalchemy, psycopg[binary], langchain, langchain-ollama, langsmith, feedparser, python-dotenv)
- [ ] Confirm Node 20+ is installed (`node -v`)
- [ ] `docker-compose.yml` for Postgres, plus `.env` and `.env.example`, plus `.gitignore` (`.venv`, `.env`)
- [ ] LangSmith setup: create an account and API key; add `LANGSMITH_TRACING`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT=command-center` to `.env` / `.env.example`; decide on `LANGSMITH_HIDE_INPUTS` / `LANGSMITH_HIDE_OUTPUTS` (see open questions)
- [ ] `ollama pull qwen3.5:2b` and confirm Ollama is running
- [ ] **Tool-calling smoke test:** script that binds one dummy tool to `ChatOllama` and checks it is called correctly 10 times in a row; confirm the runs show up in the LangSmith project
- [ ] **Decision gate:** if the smoke test passes fewer than 8/10, switch to a larger Qwen before continuing

### Phase 1: Backend foundation (~1.5 hrs)
- [ ] `db/session.py` and `db/models.py`; Alembic migrations (`alembic upgrade head`)
- [ ] `api.py`: FastAPI app, `/api/health`, static mount for `frontend/dist/` (once it exists)
- [ ] Tasks CRUD: `GET/POST /api/tasks`, `PATCH/DELETE /api/tasks/{id}`
- [ ] Notes CRUD: `GET/POST /api/notes`, `PATCH/DELETE /api/notes/{id}`
- [ ] Verify everything from FastAPI's `/docs` page

### Phase 2: Frontend shell (~2.25 hrs)
- [ ] Scaffold with `npm create vue@latest` in `frontend/` (JS, no router, no Pinia, no TypeScript, no tests); replace the empty placeholder files
- [ ] `vite.config.js`: proxy `/api` to `http://localhost:8000`
- [ ] `App.vue`: layout with three panels (Briefing, Tasks, Notes), small header with date
- [ ] `styles.css`: simple grid, light/dark via `prefers-color-scheme`
- [ ] `src/api.js`: small `api()` fetch helper
- [ ] `src/components/`: `BriefingPanel.vue`, `TasksPanel.vue`, `NotesPanel.vue`, each with `ref` state for items, loading and error
- [ ] `npm run build`, then mount `frontend/dist` from `api.py` and verify the app works from FastAPI alone
- [ ] Tasks panel: list, add, check off, delete
- [ ] Notes panel: list, add, edit, delete
- [ ] Empty, loading, and error states for each panel

### Phase 3: News briefing (~1.5 hrs)
- [ ] `news.py`: fetch and normalize items from feeds in `feeds.json`; dedupe; keep the last 24h
- [ ] `agents/llm.py`: shared `ChatOllama` factory (model, temperature, timeout from env); tag runs with the agent name and model via `tags` / `metadata`
- [ ] `news_agent.py`: summarize articles into a short markdown briefing; cap input size for the 2B context window
- [ ] `daily_job.py`: fetch -> summarize -> upsert `briefings` row for today (runnable via `python -m ...`); wrap the job and `news.py` fetch in `@traceable` so the whole run is one trace
- [ ] `GET /api/briefing/today` and `POST /api/briefing/refresh`
- [ ] Briefing panel: render markdown, "Refresh" button, last-updated time
- [ ] Schedule the job (cron or APScheduler); manual refresh is the fallback

### Phase 4: Tasks and notes agents (~2 hrs)
- [ ] `tasks_agent.py`: tools plus `POST /api/agents/tasks` ("add a task to call the dentist Friday" creates the task)
- [ ] "Plan my day" action: agent reads today's tasks and returns a suggested order
- [ ] `notes_agent.py`: auto-tag and summarize on request, `search_notes` tool
- [ ] `POST /api/agents/notes` (e.g. "what did I write about X?")
- [ ] Single agent input box in the frontend with a panel selector and a result area
- [ ] Validate tool arguments with Pydantic; return friendly errors instead of 500s

### Phase 5: Polish and wrap-up (~1 hr)
- [ ] Review LangSmith traces for each agent: check tool-call args, latency, token use and failures; fix the worst prompts
- [ ] Save 5-10 bad or good runs as a LangSmith dataset for regression checks when changing prompts or models
- [ ] Keep a minimal console log of each agent call (name, latency, error) as a fallback when tracing is off
- [ ] Verify the app works with `LANGSMITH_TRACING=false`
- [ ] Timeouts and retry-once on malformed tool calls
- [ ] README: how to run (`docker compose up -d`, `uvicorn ...`, `ollama serve`, `npm run dev` for development, `npm run build` for prod)
- [ ] Manual end-to-end walkthrough; fix the top three annoyances
- [ ] Commit and tag
